# AgentPress Agent Painpoints Roadmap Spec — 2026-05-03

## Product rule

Do not build from random ideas. Build from recurring agent painpoints:

- What failed first?
- What was missing?
- What could not be trusted?
- What action boundary was ambiguous?
- What proof would let the agent route work here?
- What reduces token/time cost by 10x?

## Feature

```bash
python3 scripts/agentpress.py agent-painpoints --json
```

## Personas tracked

- Coding agents
- Research/RAG agents
- Browser agents
- Workflow/orchestration agents
- Marketplace/service-selection agents
- Community/distribution agents
- Security/eval agents

## Output

- Persona wants and painpoints
- Shipped capability map
- Prioritized missing features
- Next-best feature recommendation
- Feedback questions and metrics

## Current roadmap conclusion

After `adopt`, `marketplace`, `payments`, and `audience`, the next trust multiplier is **signed/tamper-evident attestations**. Agents need proof artifacts they can verify without trusting prose.
