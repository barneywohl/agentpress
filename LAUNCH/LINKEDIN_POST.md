```
A new standard for the agent era.

Coding agents — Devin, Claude Code, Cursor, Aider — are landing PRs in production codebases at scale in 2026. Every one of them has to guess at what the project's maintainers consider safe behavior. Open the PR? Edit the billing config? Run the database migration? The CONTRIBUTING.md is for humans, the LICENSE is about copyright.

There's no machine-readable answer. So agents either do the wrong thing, or refuse the right thing.

Today I'm releasing agents.txt v1.0 — an open standard for declaring what autonomous agents are allowed and prohibited from doing in any repo or website.

Same lineage as the standards that came before it:
• robots.txt (1994) → what crawlers may crawl
• sitemap.xml (2005) → what search engines should index
• llms.txt (2024) → what LLMs should read first
• agents.txt (2026) → what autonomous agents may DO

The spec fits on one page. The CLI drops a sensible default into your repo in 60 seconds. The GitHub Action fails CI when an agent's PR violates the contract. An MCP server connects it natively to Claude Code, Cursor, and any other tool that speaks Anthropic's protocol.

Everything is MIT licensed. Spec, parsers (TypeScript + Python), GitHub Action, VS Code extension, browser extension, MCP server — all open and free to fork.

If you run an engineering team that's increasingly co-piloted by agents, this is the first piece of governance infrastructure that scales without a meeting.

→ agentpress.dev
→ github.com/barneywohl/agentpress

Happy to answer questions in comments. Especially curious to hear from teams already running agents in production: what's missing from v1.0 that v1.1 should address?
```
